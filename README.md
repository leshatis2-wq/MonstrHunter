# Дикие чудеса — прототип охоты 0.1

Нативное приложение для iPhone: SwiftUI + ARKit + RealityKit. Исходники подготовлены на Windows. **iOS-сборка и испытания на телефоне ещё не выполнены.** Это проект для сборки, не устанавливаемый IPA.

## Реализовано в исходниках

- Камера с запросом разрешения, обработкой отказа и возврата из фона.
- Поиск горизонтальной поверхности через ARKit raycast. После обнаружения игрок нажимает «Найти монстра».
- Мохлик: оригинальный временный 3D-персонаж из объёмных форм, около 50 см высотой. Закреплён на AR-якоре; его можно обходить.
- Четыре ранга с временными шансами появления 65 / 25 / 9 / 1 процента. Различаются цветом и сложностью ловли.
- Прицел, дистанция 0,5–3 м, кольцо точности, повторная попытка при неудаче.
- Атомарное локальное сохранение пойманных существ с уникальными ID для будущего зоопарка. Повреждённое сохранение не перезаписывается.
- Никаких карточек коллекции: в прототипе только счётчик пойманных. Зоопарк пока не реализован.

## Ограничения первого этапа

Распознаётся геометрическая поверхность, а не трава. Низкий стол тоже может подойти. На траве, бликующих и плохо освещённых поверхностях обнаружение может быть нестабильным. Сначала тестировать на хорошо освещённом полу/дорожке. Монстр вызывается кнопкой для повторяемого тестирования; автономные встречи, GPS, бросок капсулы, анимации Blender, кормление, жажда и смерть не реализованы. Ловля сейчас — прицеливание и нажатие по таймингу, не физический бросок. LiDAR не требуется и отдельные эффекты глубины пока не включены.

## Сборка без собственного Mac

Готовый `MonsterHunt.xcodeproj` включён в проект. Генератор на Python работает на Windows и macOS без дополнительных библиотек. На macOS с Xcode:

```sh
python3 tools/generate_project.py
xcodebuild -project MonsterHunt.xcodeproj -scheme MonsterHunt \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

В `.github/workflows/ios-check.yml` подготовлена ручная проверка на macOS GitHub Actions. Загружать содержимое **этой папки в корень репозитория**. После загрузки: Actions → Check iOS prototype → Run workflow. Workflow создаёт Xcode-проект, компилирует под физический iPhone без подписи и запускает XCTest на симуляторе. Workflow ещё не запущен. Тариф/доступность macOS runner нужно проверить в своём аккаунте перед запуском. Ничего не публикуется автоматически. `project.yml` сохранён как альтернативная спецификация XcodeGen; в текущем процессе он не нужен.

Такая неподписанная сборка не устанавливается на iPhone. Для TestFlight нужны Apple Developer, свой уникальный bundle ID, приложение в App Store Connect и настройка сертификатов/профиля подписи на облачном Mac. Этот этап ещё не настроен. Пароли и ключи нельзя записывать в исходники. Бесплатные лимиты Expo не относятся к этому отдельному Swift-проекту.

Разработка ориентирована на iPhone 11 и новее и SE 2/3; deployment target iOS 17.0. Более старые совместимые с iOS 17 устройства не исключены явно, но их производительность не обещается. Первый целевой тест — iPhone 17 Pro. Аппаратную пригодность проверяем через `ARWorldTrackingConfiguration.isSupported`.

## Проверка на устройстве

1. Разрешить камеру. При отказе проверить кнопку настроек и возврат в приложение.
2. Медленно поводить камерой над освещённой поверхностью. Прицел и кнопка становятся зелёными только при попадании в обнаруженную поверхность на 0,5–3 м.
3. Создать Мохлика. Отойти в сторону и обойти его: позиция остаётся на поверхности, видны бока и спина.
4. Увести прицел с монстра: ловля недоступна. Навести снова: доступна.
5. Поймать, проверить прирост счётчика ровно на один; перезапустить приложение и проверить сохранение.
6. Свернуть приложение во время ловли: отложенная попытка отменяется, награда не дублируется.
7. Проверить потерю слежения, возврат из фона и повторный поиск.
8. 10 минут непрерывной охоты: оценить нагрев, плавность, расход батареи и устойчивость позиции.

## Следующая модель из Blender

Заменить `MonsterFactory.make` загрузкой USDZ. Ориентир: метры, опора у нижней точки y=0, лицо в +Z; нормализовать размер в приложении. Игровая логика не зависит от устройства меша, при загрузке нужно создать collision shapes для прицеливания. Для первой модели достаточно одного материала/атласа и простой анимации ожидания. Сложность ограничим по тестам на реальном телефоне.
